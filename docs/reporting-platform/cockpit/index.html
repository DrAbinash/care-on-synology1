10 — Super Admin Import

How a future in-app dashboard could use these snapshots

These snapshots are designed to be imported read-only. A future in-app Super Admin dashboard could surface this data without ever claiming live analysis by treating each committed audit-data.js (or a JSON export of window.CARE_AUDIT) as an immutable, versioned artifact:

  1. Read the committed snapshot(s) from docs/reporting-platform/cockpit/ (or a generated audit-data.json) at build time — never recompute percentages at runtime.
  2. Render every score with its provenance from meta: version, auditDate, auditBaseCommit, and reviewer, plus a persistent "snapshot — not live" badge.
  3. Offer a version picker over auditHistory so admins compare snapshots (trend), while each remains labelled as a manual audit, not telemetry.
  4. Keep it behind the existing Super Admin RBAC gate; it reads static docs only — no new API, schema, or workspace coupling.

The contract: the app may display these numbers, but must attribute them to a dated manual audit and must not present them as computed-live. Regenerating a snapshot is a documentation change (edit audit-data.js), reviewed like any other doc PR.
