DICOM Q/R Pull Agent — Installation Guide

Automatic study retrieval from imaging machines into Conquest PACS
Care Diagnostics ERP
Prepared: May 2026
Technician copy

What this does

After this installation, your Conquest PACS server will automatically pull new studies from every imaging machine (MRI, CT, X-Ray, USG) at a configured interval — without any technician needing to manually push images. Studies appear in the ERP Radiology Worklist seconds after being pulled.

Patient scanned on machine → DICOM Pull Agent runs findscu (finds study) → movescu (pulls to Conquest) → ERP Worklist updated → Radiologist reports

Pre-flight checklist — confirm before starting

Conquest PACS is installed and running on this PC
This PC is on the same LAN as all imaging machines
You have the ERP URL (e.g. https://yourapp.replit.app)
You have the INTERNAL_API_KEY value (from ERP admin → Secrets)
You know each machine's IP address and DICOM AE Title
1
Install Node.js on the Conquest PC

Node.js is the runtime that the pull agent uses. It is free and safe to install alongside Conquest.

Download:  https://nodejs.org  → choose the LTS version → run the installer with default options.

After installation, open Command Prompt (search "cmd" in Start) and type:

node --version

Expected output (version number may differ):

v22.4.0
Note: If "node" is not recognised after installing, restart the Command Prompt or reboot the PC — the PATH update requires a new shell session.
2
Install DCMTK (DICOM tools)

DCMTK provides findscu (queries machines for studies) and movescu (pulls them into Conquest). These are industry-standard DICOM command-line tools.

Download:  https://dcmtk.org → Downloads → DCMTK → Win64 ZIP (latest release).

Extract the ZIP to a permanent folder:

C:\DCMTK\

Inside you will find a bin\ sub-folder containing findscu.exe, movescu.exe, and others.

Verify installation — in Command Prompt:

C:\DCMTK\bin\findscu --version

Expected output starts with:

$dcmtk: findscu v3.6.x ...
Note: Do NOT add DCMTK to the system PATH — the agent is configured to find it via the DCMTK_DIR variable you set in Step 4.
3
Copy the Pull Agent files to the Conquest PC

From the ERP project, copy the dicom-pull-agent\ folder to the Conquest PC. Place it at:

C:\DicomPullAgent\

The final folder structure should look like this:

C:\DicomPullAgent\
  src\
    index.js        ← the agent script
  package.json
  README.md
Tip: The agent has zero npm dependencies — no need to run npm install. Just copy the files and it is ready.

You can copy the files via a USB drive, shared network folder, or download from the ERP server.

4
Create the startup batch file

Open Notepad, paste the content below, and fill in your actual values. Then save as:

C:\DicomPullAgent\start-agent.bat
@echo off
REM ── Care Diagnostics DICOM Pull Agent Startup ──────────────────────────────────
REM  Edit the values below to match your environment, then save this file.

REM ERP server address (your published Replit app URL)
set ERP_BASE_URL=https://YOUR-APP-NAME.replit.app

REM Must match INTERNAL_API_KEY in your ERP environment secrets
set INTERNAL_API_KEY=PASTE-YOUR-KEY-HERE

REM AE Title this agent uses when connecting to modalities
set AGENT_AE_TITLE=DIAGNO_AGENT

REM Conquest PACS settings (check dicom.ini for MyACRNema and TCPPort)
set CONQUEST_AE_TITLE=CONQUEST1
set CONQUEST_HOST=127.0.0.1
set CONQUEST_PORT=5678

REM Path to DCMTK bin folder (where findscu.exe and movescu.exe live)
set DCMTK_DIR=C:\DCMTK\bin

REM How often to poll the ERP for new pull jobs (milliseconds)
set POLL_INTERVAL_MS=30000

REM Logging level: debug | info | warn | error
set LOG_LEVEL=info

REM ── Start the agent ────────────────────────────────────────────────────────
node C:\DicomPullAgent\src\index.js
pause
VariableWhere to find the value
ERP_BASE_URLYour ERP's published URL (e.g. https://diagnocenter.replit.app)
INTERNAL_API_KEYERP Admin → Environment Secrets → INTERNAL_API_KEY
CONQUEST_AE_TITLEOpen dicom.ini → find MyACRNema=
CONQUEST_PORTOpen dicom.ini → find TCPPort=
DCMTK_DIRThe bin\ folder inside where you extracted DCMTK
5
Register machines in Conquest's dicom.ini

Conquest needs to know about each imaging machine and about the agent itself. Open dicom.ini (in your Conquest installation folder, e.g. C:\Conquest\) and find the [ACRNema] section. Add one line per device:

[ACRNema]
; Format:  AETitle  =  IP-Address   Port
MRI_SIEMENS   = 192.168.1.10   104
CT_GE         = 192.168.1.11   104
XRAY_FUJI     = 192.168.1.12   104
USG_MINDRAY   = 192.168.1.13   104

; Register the pull agent so modalities accept C-MOVE requests from it
DIAGNO_AGENT  = 127.0.0.1      9999
Important: Use the exact AE Titles configured on each machine (case-sensitive). To find a machine's AE Title: go into its DICOM settings menu → look for "AE Title" or "SCU AE Title". Also note the machine's IP address and DICOM port (usually 104 or 11112).

Save dicom.ini and restart Conquest for the changes to take effect.

6
Test the agent manually

Double-click C:\DicomPullAgent\start-agent.bat. A Command Prompt window opens and you should see:

┌─────────────────────────────────────────────────┐
│  Care Diagnostics DICOM Q/R Pull Agent              │
└─────────────────────────────────────────────────┘
  ERP URL    : https://your-erp.replit.app
  Agent AE   : DIAGNO_AGENT
  Conquest   : CONQUEST1@127.0.0.1:5678
  Poll every : 30s
  Agent ID   : CONQUEST-PC-NAME

DCMTK findscu found ✓
[agent] Running — polling every 30s. Press Ctrl+C to stop.

Now test a manual pull from the ERP:

  1. Log in to the ERP → open DICOM Nodes
  2. Find one of your machines → click the ↓ Pull Now button
  3. Switch to the Pull Jobs tab — watch status change: pending → running → completed
  4. Check the Conquest viewer — the pulled studies should appear
If it shows "failed": The agent Command Prompt window will print the DCMTK error. Common causes: wrong machine IP, machine AE Title mismatch, machine's Q/R SCP not enabled, or a Windows Firewall rule blocking port 104. Check each machine's DICOM service settings to ensure Q/R SCP is enabled.
7
Install as a Windows Service (auto-start with Windows)

Use NSSM (Non-Sucking Service Manager) — a free, single-file tool that runs any program as a Windows Service with no programming required.

Download NSSM:  https://nssm.cc/download → extract → copy nssm.exe to C:\DicomPullAgent\nssm.exe

Open Command Prompt as Administrator (right-click → Run as administrator):

C:\DicomPullAgent\nssm.exe install DicomPullAgent

A GUI window opens. Fill in the fields:

TabFieldValue
ApplicationPathC:\Program Files\nodejs\node.exe
ApplicationStartup directoryC:\DicomPullAgent
ApplicationArgumentssrc\index.js
Environment(one per line)All variables from Step 4 (without "set " prefix)
DetailsDisplay nameCare Diagnostics DICOM Pull Agent

Click Install service. Then start it:

C:\DicomPullAgent\nssm.exe start DicomPullAgent

Verify it is running:

sc query DicomPullAgent

Expected output includes: STATE : 4 RUNNING

Result: The agent now starts automatically every time Windows boots, even without anyone logging in — exactly like Conquest itself.
8
Enable Auto-Pull in the ERP for each machine

The final step is to turn on automatic scheduling in the ERP for each imaging machine:

  1. Log in to the ERP → go to DICOM Nodes
  2. Click Edit on the first machine (e.g. CT Scanner)
  3. Scroll to the Auto-Pull (DICOM Q/R) section → toggle it ON
  4. Set Pull frequency — recommended: Every 15 min for active machines
  5. Set Query days back — Today only is sufficient for live operation
  6. Leave Conquest fields blank (agent uses its default settings from Step 4)
  7. Click Save Changes
  8. Repeat for MRI, X-Ray, USG machines
What happens next: The ERP cron scheduler runs every 5 minutes. When a machine's interval is due, it creates a pull job. The agent on this PC picks it up within 30 seconds, queries the machine for today's studies, and pulls each one into Conquest automatically. The studies appear in the ERP Radiology Worklist → radiologist can open them in Weasis and generate a report.
