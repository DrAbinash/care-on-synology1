PROBLEM
═══════════════════════════════════════════════════════════════════════════════
  ✗ care-db-patch-v2 crashes during startup
  ✗ Error: "relation radiology_quick_findings does not exist"
  ✗ Deployment pipeline halts at stage 2 of 6
  ✗ API never starts; diagnostic center can't access system

ROOT CAUSE
═══════════════════════════════════════════════════════════════════════════════
  Feature migrations run in ALPHABETICAL ORDER:
  
  ❌ add_abnormality_engine.sql (runs FIRST)
     └─ Tries to ALTER radiology_quick_findings table
  
  ❌ add_radiology_quick_findings.sql (runs LATER)
     └─ Creates the radiology_quick_findings table
  
  Problem: Abnormality engine tries to use table BEFORE it's created!
  
  Like trying to paint a wall that doesn't exist yet.

SOLUTION
═══════════════════════════════════════════════════════════════════════════════
  1. RENAME FILE (forces correct order)
     add_abnormality_engine.sql → z_add_abnormality_engine.sql
     
     Now runs LAST (z prefix sorts after a,b,c...y)
  
  2. ADD GUARDS (safe if table doesn't exist)
     DO $$
       IF EXISTS (SELECT 1 FROM information_schema.tables 
                  WHERE table_name = 'radiology_quick_findings') THEN
         ALTER TABLE ...
       ELSE
         RAISE WARNING 'Table not found; skipping'
       END IF;
     END $$;
  
  3. MAINTAIN IDEMPOTENCY (safe to run multiple times)
     ADD COLUMN IF NOT EXISTS ...
     UPDATE ... WHERE ... = ''  (never overwrites)
